# Mode 1: greenfield

Nobody knows the shape yet; only the need is clear. Walk the design tree in
this order, resolving dependencies first: problem and need, outcome and
success, users, scope, domain language, core journeys (every failure path),
data, integrations, non-functional needs, risk and regulation, rollout,
delivery risks.

The PM may paste raw developer discussion instead of a clean answer. Then:
extract each position with its owner, record only decisions actually
reached, record open disagreements as Q entries with both positions, and
say in `challenge` what you recorded so the PM can correct it.

If a branch is stuck, park it: a Q entry with status Parked, then move to a
branch that does not depend on it.

Challenge: a need stated as a solution; success with no number; scope with
no out-of-scope list; journeys with no failure path; new customer data with
no retention answer.
